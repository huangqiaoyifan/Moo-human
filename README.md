# 艺术赏析文本评审

GitHub Pages 静态盲评界面，面向 3 位评审者、50 张样本图片和 8 种生成方法。页面不向服务器发送评分；每位评审者的进度保存在自己的浏览器中，完成后下载 CSV 交回研究团队。

## 样本与方法

- 固定随机种子 `20261117`，从 274 张图中抽取 50 张。
- 先按规范化寓意名称去重，再按功名仕途、家族繁衍、长寿延年、富贵财禄、安宁和合、喜庆吉祥、丰收繁盛等核心含义组合归组；每个含义组合最多 3 张。抽取时兼顾关键事实概念数量的低、中、高层次。
- 结果用于人工评审试点中的方法对比，不作为 274 张全集的无偏估计。
- 8 种方法：MOO、Gemini-3.8-Flash、GLM-5.3、ExpArt-KG-zh、Evidence-Only、Full-Graph-S、MOO-N、Image-Only。
- 消融组不含 MOO-E，与确认的对比设计一致。

## 本地预览

在本目录运行：

```powershell
python -m http.server 8080
```

浏览器访问 `http://localhost:8080`。不要直接双击 `index.html`，浏览器会阻止本地 JSON 数据读取。

## 发布到 GitHub Pages

把本目录内容放入一个公开 GitHub 仓库的根目录，推送到 `main` 分支。仓库包含自动部署工作流 `.github/workflows/pages.yml`；在仓库 Settings → Pages 选择 GitHub Actions。部署完成后，邀请三位评审者打开 Pages 地址。网页文件、50 张图片和盲化文本会公开可访问，这符合当前评审材料可公开的约定。

本工作区没有配置网站仓库的 Git remote 或 GitHub CLI 登录，因此这里只准备好 Pages 发布包，尚未替你创建远程仓库或推送。

## 评审者步骤

1. 输入评审者姓名。三位评审者使用各自姓名，并评完全相同的样本；姓名仅写入本地评分文件，不会发送到网站服务器。
2. 结合原图及页面显示的参考文化寓意，依次为每段文本的四个维度打 1–5 分。每位评审者看到的文本顺序按图片随机打乱，页面不显示方法名称。
3. 评分自动保存在该浏览器。每次结束评审前，点击“保存 / 导出”下载 Excel 留档；之后在另一台电脑或清理浏览器数据后，可用右上角导入按钮上传此 `.xlsx` 文件继续。导入时需使用相同的评审者姓名。
4. Excel 留档保留全部 400 个文本编号，未评分单元格留空；不要删除行或修改文本编号。也可下载 JSON 作为备用恢复文件。
5. 完成全部 400 段文本后，点击“保存 / 导出”下载 CSV 并交给研究团队汇总。最终 CSV 和中途 Excel 留档分开使用。

## 评分汇总

研究者将三位评审者的 CSV 放到一个目录，再运行：

```powershell
python ../人工评审研究者文件/scripts/aggregate_reviews.py --reviews <评分文件夹> --key ../人工评审研究者文件/method_key.csv --out <汇总输出目录>
```

脚本校验三位不同姓名的评审者是否各自覆盖全部 400 条文本，输出方法 × 维度均分、逐图逐文本合并分数，以及四个维度分别的序数 Krippendorff's alpha。综合总分不自动计算，保留四个维度分别解释。

研究者私有文件 `../人工评审研究者文件/` 包含方法盲化映射表与样本清单，不属于网站文件，切勿上传到公开仓库。
